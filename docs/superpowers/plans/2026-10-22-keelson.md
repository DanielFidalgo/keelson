# Keelson Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship Keelson's first release: scheduled probes of remote MCP servers, content-addressed snapshots, drift classification, deduplicated incidents, signed webhook alerts, a REST API, deployed to GCP with Pulumi.

**Architecture:** Onion monorepo. `packages/domain` is pure logic, `packages/application` holds use cases and the ports they need, `packages/infrastructure` implements the ports (Postgres, Cloud Tasks, Secret Manager, MCP SDK client, webhook channels). `apps/api` and `apps/worker` are Fastify services on Cloud Run and act as composition roots; `apps/demo-server` is a controllable MCP server; `apps/dashboard` is a Vue SPA served by `api`.

**Tech Stack:** Node 24, npm workspaces, TypeScript 6.0, Vitest 5, Fastify 5 + fastify-openapi-glue, `pg`, Testcontainers, MCP TypeScript SDK v2 (`@modelcontextprotocol/client`, `/server`), `standardwebhooks`, undici, Vue 3 + Vite 8, Pulumi (TypeScript) on GCP, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-10-22-keelson-design.md`

## Global Constraints

- Runtime Node 24, ESM only (`"type": "module"`), TypeScript `6.0.3` exactly (typescript-eslint 8.72 requires `<6.1`; do not use TS 7).
- Versions (caret ranges at these majors): vitest 5.0.5, fastify 5.12.7, fastify-openapi-glue 4.12.0, @scalar/fastify-api-reference 1.75.1, @fastify/static 10.1.7, pg 8.23.1, @testcontainers/postgresql 12.2.1, zod 4.6.7, @modelcontextprotocol/client 2.3.1, @modelcontextprotocol/server 2.3.1, standardwebhooks 1.1.1, undici 8.12.3, @google-cloud/tasks 7.3.0, @google-cloud/secret-manager 7.2.0, google-auth-library 11.3.1, pino 10.4.0, eslint 10.13.0, typescript-eslint 8.72.0, dependency-cruiser 18.7.0, openapi-typescript 7.13.0, vue 3.5.44, vue-router 5.4.0, vite 8.3.5, @vitejs/plugin-vue 6.0.10, @vue/test-utils 2.5.1, happy-dom 21.0.4, @pulumi/pulumi 3.271.0, @pulumi/gcp 10.2.0, tsx 4.23.15, @types/node ^24, node-pg-migrate 9.0.0, awilix 13.0.5, @fastify/awilix 8.3.1.
- Dependency rule (enforced by dependency-cruiser in CI): `domain` imports nothing outside itself except `node:crypto` (hashing is pure computation); `application` imports `domain` only; `infrastructure` imports `application` and `domain`, never `apps/*`; `apps/api` never imports `infrastructure/src/network` or `infrastructure/src/inspector/sdk-mcp-inspector.ts` (only `worker` reaches user-supplied URLs). Those untrusted-egress adapters (`network/`, `sdk-mcp-inspector`, `alerting/`) are exported only from the subpath `@keelson/infrastructure/egress`, never from the package's main entry, and `apps/api` may not import that subpath. `awilix` and `@fastify/awilix` are imported only from `apps/*` (rule `di-only-in-composition-roots`).
- Dependency injection: awilix in `InjectionMode.PROXY`, so every class keeps its single deps-object constructor and `domain`/`application` stay library-free. Each app's `container.ts` is its only composition root: it registers config with `asValue`, adapters and use cases with `asClass(...).singleton()`, and returns the `AwilixContainer`. Tests and e2e replace registrations (`container.register({ clock: asValue(fixedClock) })`) instead of passing override arguments. Fastify routes resolve dependencies through `@fastify/awilix` (`fastify.diContainer`).
- Migrations: node-pg-migrate with plain SQL files in `packages/infrastructure/migrations/`, named `NNNN_<what>.sql` (`0001_initial.sql`, `0002_...`), each starting with a comment explaining why the change exists, using idempotent DDL (`IF NOT EXISTS`) and `-- Up Migration` / `-- Down Migration` sections. node-pg-migrate's tracking table and advisory lock make re-runs safe.
- Domain values pinned by the spec: minimum interval `300` s; probe budget `10` s; `down` after `3` consecutive non-`up` probes; webhook endpoint disabled after `10` consecutive failed deliveries; probes never call tools.
- Aggregates are immutable records; the behaviour that governs them lives as functions in the same module. Domain validation errors throw `DomainValidationError` carrying every problem (`problems: string[]`).
- All configuration from environment variables, parsed once with zod in each app's `config.ts`. Names: `PORT`, `DATABASE_URL`, `GCP_PROJECT`, `GCP_LOCATION`, `PROBE_QUEUE`, `WORKER_URL`, `API_URL` (the api's own URL, default OIDC audience for `/internal/dispatch`), `SECRET_STORE` (`gcp` | `file`), `SECRETS_DIR`, `INTERNAL_AUTH_MODE` (`oidc` | `static`), `INTERNAL_STATIC_TOKEN`, `OIDC_AUDIENCE`, `INTERNAL_INVOKER_EMAILS` (comma list), `TASKS_INVOKER_EMAIL`, `ALLOW_PRIVATE_TARGETS` (`true`|`false`), `ALLOW_HTTP_TARGETS`, `DEMO_ADMIN_TOKEN`.
- `User-Agent` on every outbound request: `Keelson/0.1 (+https://github.com/DanielFidalgo/keelson/blob/main/docs/probes.md)`.
- Logs: pino JSON on stdout; field `logging.googleapis.com/trace` from `X-Cloud-Trace-Context`; include `monitorId` and `slot` where relevant; never log secrets or full tool payloads.
- Public repo hygiene: no em dashes, no real personal data in code, tests, docs or committed config.
- Commits: the maintainer commits. Each task ends by printing one `git add` + `git commit` command (source and tests together), conventional message, no `Co-Authored-By` or other attribution. Never run git write commands.
- Test commands: run only the task's own test files, never the whole suite.

## Decisions this plan adds to the spec

- The canonical catalog keeps only the fields drift classification compares (tool: `name`, `description`, `inputSchema`; prompt: `name`, `description`; resource: `uri`), so two snapshots differ exactly when there is at least one change. Every `enum` is sorted by canonical JSON and deduplicated. Prompt arguments, resource names and resource descriptions are therefore not watched in this release.
- Severity of kinds the spec leaves open: `prompt_removed` and `resource_removed` are `critical`, `prompt_added` and `resource_added` are `warning` (mirrors tools).
- Schema changes are `compatible` only when every difference is: optional property added, enum value added, or `description`/`title`/`default`/`examples` changed. Anything else is `breaking`.
- `incidents` gains a `resolution` column (`recovered` | `approved` | `reverted`); `monitors` gains `created_at`.
- In-memory port implementations live in `packages/application/src/testing` (exported as `@keelson/application/testing`) so application tests do not import outward. Local development replaces Cloud Tasks with `HttpProbeQueue` (direct call to `worker`).
- Cloud Tasks has no dead-letter queue. On the final retry the worker logs `probe.retries_exhausted` at `ERROR`, and a Pulumi log-based alert policy notifies (replaces the spec's "dead-letter queue, which alerts").
- With Neon as the database, `api` needs internet egress to reach it, so "only `worker` reaches the internet" is enforced in code (the dependency rule above), not by network policy.
- Webhook delivery backoff: `next_attempt_at = now + min(2^(attempts-1), 60) minutes`.

## Review Focus

1. A probed server that never finishes responding: the probe must end as `timeout` within the 10 s budget, not hang the worker (test in Task 7).
2. A server whose pagination cursor never ends: stop after 50 pages and record `protocol_error` (test in Task 7).
3. A webhook URL that redirects to `169.254.169.254` or resolves to a private address: no request leaves, the delivery counts as failed (test in Task 8).
4. A monitor deleted or paused after its task was queued: `RunProbe` finishes successfully without writing, so Cloud Tasks does not retry (test in Task 5).
5. A server listing two tools with the same name: canonicalisation rejects it and the probe records `protocol_error` instead of crashing (test in Task 2, mapped to an outcome in Task 5).
